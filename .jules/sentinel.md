## 2024-05-24 - Hashed Content Security Policy (CSP) for Static HTML
**Vulnerability:** Static HTML pages without a Content Security Policy (CSP) are at a higher risk of Cross-Site Scripting (XSS) if they are ever modified to include user input or if external resources are compromised. By allowing 'unsafe-inline' styles or external resources by default, any injected malicious script could potentially run.
**Learning:** For a purely static HTML project with inline styles, it is a significant security enhancement to lock down the CSP completely. The most secure approach is to use a `<meta http-equiv="Content-Security-Policy">` tag that denies everything by default (`default-src 'none'`), disallows base URIs (`base-uri 'none'`), disallows form actions (`form-action 'none'`), and only allows the exact inline styles present on the page using a SHA-256 hash (`style-src 'sha256-...'`). This creates a very strict defense-in-depth measure.
**Prevention:** Always implement a strict CSP for static HTML files. Instead of using `'unsafe-inline'` for styles, calculate the SHA-256 hash of the inline CSS block and use that in the `style-src` directive. Any future changes to the CSS or additions of external resources/scripts must involve explicitly updating the CSP to allow them, preventing accidental or unauthorized resource execution.
