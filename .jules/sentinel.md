## 2024-03-21 - Manual CSP Hash Management for Static Sites
**Vulnerability:** The static HTML files (`index.html`, `privacy.html`) were missing Content Security Policy (CSP) headers, exposing them to potential inline script injection, even though they only used inline styles. Using `'unsafe-inline'` for styles is not recommended, and without a CSP, there is no defense in depth.
**Learning:** This project is a purely static site without a build system (like Webpack or Vite) to automatically generate CSP hashes for inline assets. Because of this, hashes for inline `<style>` tags must be calculated manually (e.g., using `openssl dgst -sha256 -binary | openssl base64`) and hardcoded into the `<meta>` CSP tags.
**Prevention:** Always ensure a strict CSP is implemented, even on purely static sites. For projects without build systems, remember the manual hashing process for any changes to inline CSS or JavaScript. Do not default to `'unsafe-inline'` just because there's no automated tooling.
