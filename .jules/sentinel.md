## 2024-11-23 - Add Content Security Policy to Static HTML Files
**Vulnerability:** The purely static HTML files (`index.html` and `privacy.html`) lacked Content Security Policy (CSP) headers or meta tags, leaving them unprotected against potential cross-site scripting (XSS) or other content injection attacks if any dynamic features are added later or if hosting infrastructure is compromised.
**Learning:** For a repository with no build system, no package manager, and only static HTML files, we must manually inject CSP `<meta>` tags and manually calculate SHA-256 hashes for any inline styles (`style-src`) since we cannot rely on tools like Webpack or Vite to generate them.
**Prevention:** Any future modifications to inline CSS or additions of scripts, external assets, or form actions will require updating these CSP `<meta>` tags and manually recalculating hashes (e.g., via `python3 -c "import hashlib, base64; print(base64.b64encode(hashlib.sha256(b'YOUR_CSS').digest()).decode('utf-8'))"`).
